`.agents/skills/` is the single skill store; `.claude/skills/` and `.crush/skills/` symlink into it. The symlinks were staged for commit while `.agents/` itself was untracked — that commit would ship dangling symlinks and zero skill content.

Symlinks are derived per-harness glue (regenerated by the skills installer) and degrade to plain text files on Windows checkouts without `core.symlinks`. They do not belong in git.

## Summary of Changes

`.gitignore` now ignores `.claude/skills/` and `.agents/skills/` outright — the repo tracks no skills at all. Rationale: `bunx skills experimental_install` restores every lock-managed skill AND the per-harness symlinks from `skills-lock.json`, so committing either would vendor a derived artifact — and a committed symlink degrades to a plain text file on a Windows checkout without `core.symlinks`. `quarkus` is not in the lock, but it is written by the `quarkus-agent` MCP already configured in `.mcp.json`, and the same content is installed globally at `~/.agents/skills/quarkus` (byte-identical). Vendoring it would have put 900K of generated docs in the repo and let a stale project copy shadow the fresher global one.

The 75 previously-committed `.claude/skills/daisyui/**` files are deleted — that content moved to `.agents/skills/daisyui/` and is now installer-managed. `skills-lock.json` carries the upstream daisyUI refresh (new `aura`, `megamenu`, `otp` components) that bumped its `computedHash`. `.claude/settings.json` (SessionStart `beans prime` hook) stays tracked; it is real config, not derived. CLAUDE.md gained an `## Agent skills` section naming the restore command, so a fresh clone does not silently come up with no skills.
